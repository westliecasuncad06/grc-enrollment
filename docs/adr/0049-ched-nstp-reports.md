# ADR 0049 — CHED Enrollment List and NSTP Forms 2-B / 2-A for the Registrar Head

**Status:** Accepted
**Date:** 2026-10-14
**Related:** PRD FR-ANL-007 (government / CHED-style reports), ADR 0017 (aggregate-only dashboards), ADR 0024 (audited student-level reads), ADR 0038 (acting context).
**Spec:** `docs/superpowers/specs/2026-10-14-ched-reports-design.md`

## Context

GRC submits four documents to CHED NCR: the Enrollment List (`template_2024.xlsx`), NSTP Form 2-B for the students enrolled in NSTP 1 and NSTP 2, NSTP Form 2-B for the NSTP 2 graduates, and the one-row NSTP Form 2-A summary. The owner supplied the four templates and asked that the Registrar Head can view each one and download it as CSV or as Excel in the template's own format. The system stored none of the personal details the forms ask for (gender, birth date, citizenship, contact number, a street / town / province address), and the owner asked for the missing ones to be populated.

## Decisions

1. **Registrar Head only.** A new module "CHED Reports" and two routes, `GET /api/v1/ched-reports/{report}` (preview) and `GET /api/v1/ched-reports/{report}/export?format=csv|xlsx`, behind `role:registrar_head` and the `view-ched-reports` gate (`ChedReportPolicy`). The lists are named students with birth dates and contact details; this is the audited student-level read ADR 0024 allows for authorised roles. The first page of a preview writes `ched_report.viewed`; every download writes `ched_report.exported` (report, term, format, row count; no student, no contact data).
2. **One source of rows.** `BuildChedReport` builds the rows once; the preview, the CSV and the Excel file all read them. Counted: students who are not `is_demo_account` with an `enrolled` enrollment in the term (the CHED list), that with a not-dropped `NSTP...` subject (NSTP Enrollment), or a LOCKED passing grade (`GradeMark::isPassing()`) for `NSTP2` in the term (NSTP Graduates). Form 2-A counts the ONE chosen term, split M / F: only that term's semester block carries the NSTP enrollment numbers and the term's graduates (the students who passed NSTP 2 in it); every other block, ROTC, LTS and Summer are 0. CWTS only (GRC offers CWTS). NSTP 1 is taken in the first semester and NSTP 2 in the second, so the NSTP enrollment list of a first-semester term holds only the students enrolled in NSTP 1 and that of a second-semester term only NSTP 2 (any other term: any NSTP subject); its title and tab say so (`NSTP 1 Enrollment (Form 2-B)`, `NSTP 2 Enrollment (Form 2-B)`), and the file name too (`NSTP1-Form-2B-Enrollment_2025-2026-1st`). The Form 2-A file is named per term (`NSTP-Form-2A-Summary_2025-2026-1st`).
3. **Excel = the owner's template, filled.** The four templates live in `backend/resources/ched-templates/`. `ChedWorkbookWriter` copies a template package and rewrites only its first worksheet with `ZipArchive`: data rows cloned from the template's own first data row (same styles), the NSTP footer moved below the rows with its merges and `COUNTIF` ranges and cached values, text as inline strings, `calcChain.xml` dropped and `fullCalcOnLoad` set so Excel rebuilds it. The logo, merged cells, page setup and the signatories stay as CHED sent them. No Composer dependency: PhpSpreadsheet needs `ext-gd`, which the local PHP does not have; `ZipArchive` is on both. The output was first loaded with a strict third-party reader (openpyxl, outside the repo); on 2026-10-15 it was also opened and rendered in Excel itself (see the follow-up).
4. **CSV = the template's column headers, then the rows.** UTF-8 with a byte-order mark, CRLF. Text a spreadsheet would run as a formula (`=`, `@`, a leading tab, or a `+` / `-` that is not a phone-number shape) gets a leading apostrophe.
5. **Template rules kept.** Program written in full and the major split off (`BS ... major in ...`); Major and Name Extension empty, never "N/A"; the Form 2-B Gender column is `MALE` / `FEMALE` (the footer counts those words), the CHED list uses `M` / `F`; Serial No. is empty (CHED issues it after submission, assumed); Remarks empty; the middle name column holds the stored middle initial with a dot (the system stores no full middle name); the NSTP "Street/Barangay" column falls back to the free-text `address` when the split address is empty.
6. **Missing details are populated, and recognisable.** Eight nullable columns on `student_profiles` (`gender`, `birth_date`, `citizenship`, `contact_number`, `street_barangay`, `town_city`, `province`, `demographics_demo_fields`; migration `2026_10_15_000001`, reversible). `php artisan students:populate-demographics` (`--dry-run`, `--wipe`) fills only empty fields of non-demo students and never overwrites a value: gender from the first name (known Filipino given names, then name-ending rules, then a deterministic pick from the profile id, each counted separately in the output), citizenship `Filipino`, and birth date, contact number and the street / town / province split as deterministic generated values. The split address is generated only when the student has no written address. Every field it writes is listed in `demographics_demo_fields`, `--wipe` takes back exactly those, and one summary audit row is written. The API reports how many listed students carry such details (`report.demo_populated`); the preview used to warn with that count and no longer does (see the follow-up of 2026-10-15, last bullet).

### Follow-up, 2026-10-15 (owner's review of the first deploy)

- The on-screen table shows only the columns needed to find a student (it fits the page without scrolling sideways); clicking a row, or its name, opens a modal with every field of the file under the template's labels and the subjects as a list. The modal is wide and laid out in columns so that all of it is on screen; its own scroll only applies to a screen too small to hold it.
- A search box finds a student by name or student number (every word must match; `GET /ched-reports/{report}?search=`). It narrows the preview only: a download always has every student of the term, and the audit row of a preview records that a search was used, never the words.
- The term pickers list school years and semesters newest first (by school year, then semester), not by the order the terms were created in.
- Form 2-A is per chosen term, as above, instead of the whole school year.

### Follow-up, 2026-10-15 (Admission captures the details)

- **Create Account asks for them.** Admission's Create Account form (and the correction dialog of a student record) now has Gender, Birth date, Citizenship (starts `Filipino`), Contact number, Street / barangay, Town / city and Province. They are required for a new account (`StoreStudentProfileRequest`) and optional in a correction (`UpdateStudentProfileRequest`); a blank detail on an older account is left as it is and never sent. A detail Admission changes to a new value is a real value, so it is removed from `demographics_demo_fields` (a value sent unchanged is not a typed one and stays generated, because the correction form sends every field it shows); the API exposes the remaining ones as `generated_fields` and the correction dialog tells Admission "Generated for the demo. Enter the student's real value."
- **One address source.** The single `address` text is written by the server from street / barangay, town / city and province (`App\Domain\Identity\StudentAddress`, "street, town, province"); `address` is refused on create and on correction, so the text and its three parts never disagree. A correction of one part rewrites the text from the stored parts, but only once all three are known: a partly typed address on an older account keeps its free text until the third part is entered.
- **Regular / Irregular is not asked for.** The category select is gone from the form and `enrollment_category` is refused (422) on create and on correction: the system decides it (ADR 0021, 0047). A new account starts Regular, `enrollment_category_derived_at` stays `NULL`, and the grade-based reclassification or the approval of a transferee's credits changes it later.
- The audit rows of creating and correcting an account still carry no contact data: only field names and counts.
- The preview no longer shows the "Some details are generated, not real" note: the owner knows the details are not real and asked for it to go (2026-10-15). `report.demo_populated` is still returned by the API; only the "Gender missing" warning remains on the screen. Anything submitted to CHED still needs the real values, which Admission now captures for new accounts.
- **The downloaded Excel files look like the owner's templates (owner's review, 2026-10-15).** The files were already the templates filled in, with the logo, the header band and the merged cells, but opened in Excel the NSTP lists showed the data in the workbook's default serif font and cut a program name, a street or the word FEMALE off at the edge of a narrow column, and the Enrollment List cut its subject list off. `ChedWorkbookWriter` now gives every data cell of a list the headings' font (Calibri 10; the Enrollment List keeps the template's Tahoma 10), the template's borders and fills and a centred or wrapped alignment (new `cellXfs` entries copied from the template's own), widens the columns that hold long text (the NSTP lists: course 64, street 40, e-mail 36, ...; the Enrollment List: programs 48, subjects 72), wraps the Enrollment List's subject list inside its cell and makes that row taller, and anchors the NSTP forms' logo again at its own size (`oneCellAnchor`, 647699 x 609600 EMU) at the same distance from the centred title as in CHED's template, because it was stretched between two cells and the title moves right when the table grows. Form 2-A (the summary) was not changed: it already matched. Checked by opening the files in Excel itself, as generated from the production data, next to the templates.
- Saved Create Account drafts (`admission.create-account.v1`) are not read any more (`.v2`), because an old draft would carry the removed `address` and `enrollment_category` and the strict schema would refuse it.

## Consequences

- **The downloaded files look like real data.** The generated birth dates, contact numbers and addresses are demo values (owner option A, chosen for the presentation). Before any file is submitted to CHED, Admission must enter the true values, or the owner must accept the generated ones knowingly. Admission captures the details for every account it creates from 2026-10-15 on (follow-up above); a student admitted between the command run and that change has none until the command is run again or Admission corrects the record.
- Gender from a first name is a guess; the command's output says how many names were decided by name, by ending and by fallback.
- Year level on the CHED list is the student's current year level, not a stored per-term value.
- The migration must be run before the new code is used; nothing existing changes until the command is run.
- PhpSpreadsheet can replace `ChedWorkbookWriter` later without touching the rows or the API.
